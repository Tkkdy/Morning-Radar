vLLM v0.29.0 发布：Model Runner V2 成为默认，新增多种模型支持

vllm-project/vllm 发布了 v0.29.0 版本，包含 594 个提交，来自 277 位贡献者。

为什么重要：降级模式下暂时无法生成重要性分析，请查看已验证事实与来源。

已宣布
GitHub · vllm-project/vllm · Release 主来源 Release 发布于 2026-09-09

不确定性：AI 晨报分析暂时不可用。

查看详情

已验证事实

  • Model Runner V2 (MRV2) 现在成为所有模型的默认运行器，完成自 pooling 模型开始的推广。
  • MRV2 新增了 CUDA graph 内存剖析、批分片采样、prompt embeds、extract_hidden_states 推测解码、padded FULL cudagraph 分发和 DP-sync 跳过等功能。
  • MRV1 仍用于一些 ROCm 模型和不支持 MRV2 的功能。
  • 新模型支持包括 Tencent 的 Hy4-preview、Qwen3.8-Flash-Next、GraniteSWA 和 GraniteMoeSWA、NemotronH_Omni_Reasoning_V3 和 Kimi K3 NVFP4 检查点。
  • 针对 Kimi-K3 和 DeepSeek V4 的性能优化包括融合 MXFP4 top-k 终结、K3 Mamba 元数据准备、低延迟 GEMM、GEMM-RS 扩展到 GEMM-AR、MLA 门融合、共享专家融合到 MegaMoE、自适应 top-k 宽度和 SwiGLU clamp 内核。
  • 推测解码新增了 per-request 接受统计、对 logprobs 的自适应验证、SM100 稀疏 MLA、Qwen3-Omni DSpark drafts、PLaMo3 EAGLE-3/DFlash 和 DFlash2 加载。
  • RL 权重同步新增了 sharded_rdt P2P 后端、rank-local IPC 权重更新、稀疏检查点坐标更新和路由专家加载。
  • Mamba 前缀缓存通过内部预填充检查点带来 TTFT 改善，prefix_cache_retention_interval 成为命令行参数，默认值为 0。
  • 新默认值包括：FlashInfer 全归约默认启用、确定性前缀缓存 NONE_HASH、新的 --max-num-queued-reqs 和 --max-num-queued-tokens 标志。
  • 破坏性更改包括移除十个已弃用的模型架构、将 FlexOlmo/Olmo3/Hunyuan V1/VL 迁移到 Transformers 后端、移除 PyAV 视频解码器、弃用 python -m vllm.entrypoints.openai.api_server 并移除测试环境变量。

分析

  • MRV2 成为默认标志着一个重要的过渡完成，可能提高所有模型的一致性和可维护性。
  • 新模型的加入表明 vLLM 正在积极扩展对最新 MoE 架构和硬件（如 SM100）的支持。
  • 对 Kimi-K3 和 DeepSeek V4 的特定优化表明 vLLM 正在与这些模型提供者紧密合作。
  • RL 权重同步的新后端是为满足大规模训练同步需求。
  • 破坏性更改是清理技术债务和推动现代实践的一部分。

不确定性

  • MRV1 对 ROCm 模型的支持持续时间不确定。
  • 多个破坏性更改的影响范围需要进一步评估。
实体：vllm-project/vllm、Tencent、Kimi、DeepSeek产品：vllm主题：ai_infrastructure、open_source_ai
