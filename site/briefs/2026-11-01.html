pydantic-ai 发布 v2.64.0，包含兼容性说明、新特性与多项能力更新

pydantic 在 GitHub 发布 pydantic-ai v2.64.0，发布日期为 2026-10-30，发布说明由 dsfaccini 提交。

为什么重要：该版本同时包含兼容性变更和功能新增，对使用 pydantic-ai 的开发者而言，升级时需要关注 ModelHTTPError 行为、服务端状态 ID 的回传范围以及 Coder 严格 tool schema 默认值的变化。

GitHub · pydantic/pydantic-ai · Release 主来源 Release 发布于 2026-10-30

不确定性：发布说明内容为截断的 excerpt，v2.64.0 的完整变更列表未能全部获取。

查看详情

已验证事实

  • 该版本在兼容性说明中列出：将重试传输放弃时的错误状态抛出为 ModelHTTPError，以便 fallback 继续推进（PR #11934）。
  • 兼容性说明还包括：通过 Model.accepts_server_state，仅将存储的 response、item、conversation 和 container ID 发送回创建它们的端点（PR #11774）。
  • json-repair 被改为可选依赖，仅 Coder 和 RepairToolArguments 需要（PR #11768）。
  • Coder 的工具默认关闭严格 tool schema，可通过 Coder(strict=True) 选择启用（PR #11743）。
  • 新特性包括：@agent.system_prompt(dynamic=True) 支持以 on_change='append' 追加变更以保留缓存提示（PR #11445）。
  • 新特性包括：新增 BoxdSandbox，可在 boxd 机器中运行 Coder、Shell、FileSystem 等 harness 能力（PR #11367）。
  • 新特性包括：新增 ModelFallback 能力、每次尝试的 prepare_model_request 钩子以及 RetryModelRequest（PR #9348）。
  • 新特性包括：在 Azure AI Voice Live 上新增 output_speech_timestamps 以报告实时语音的词级时间（PR #11685）。
  • 新特性包括：新增 Harness Reminder(scope='conversation')，用于保留在消息历史中的提醒（PR #11642）。
  • 发布说明还提到修复 AnthropicModel.count_tokens 拒绝全部延迟的 tool request 以及低估服务器工具计数的问题（PR #11343）。

分析

  • 将 json-repair 改为可选依赖有助于减小基础安装体积，但依赖 Coder 或 RepairToolArguments 的用户需显式安装。
  • ModelFallback 相关能力（能力本身、prepare_model_request 钩子和 RetryModelRequest）在同一版本中集中出现，表明模型回退与重试机制是该版本的重点方向。

不确定性

  • 发布说明未提供各 PR 的详细行为说明，部分兼容性变更的具体影响范围无法从现有摘要确认。
