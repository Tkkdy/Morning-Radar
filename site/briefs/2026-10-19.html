vLLM 发布 v0.32.0：集中式决策接口、低精度 KV 缓存与 Model Runner V2 更新

vLLM 发布 v0.32.0，该版本包含来自 363 位贡献者（其中 121 位为新贡献者）的 814 个提交。新版本引入 POST /v1/systemone 端点，可在结构化状态上回答 choice、noul 和 score 类问题，默认启用，并已在 Cloudflare/clef-omni、LiquidAI/d1-3B 和 DiffusionGemma 上运行。同时新增 hf 工具与推理解析器（--tool-call-parser hf、--reasoning-parser hf），读取检查点的 response_template，Python 与 Rust 前端均支持。 硬件与精度方面，NVFP4 KV 缓存扩展至 SM8x、SM12x 及 SM90，SM12x 上支持 XQA 解码，SM100 上支持 MiniMax-M3 稀疏注意力；GLM-5.x 在 SM100 上默认使用 FP8 KV 缓存；SM90 上的 fp8_ds_mla 使 GLM-5.3-Flash 输出吞吐最高提升 31%；ROCm 新增 4-bit ultraquant_4bit KV 缓存。Model Runner V2 新增变长草稿的 GPU n-gram 推测器、Elastic EP、为 MLA 模型引入带预填充上下文并行的流水线并行，以及原生 torch.compile 模式，MRV2 现为 ROCm 默认。启动与服务加速方面包括 vllm download-kernels、vllm preload --preload-autotune、共享内存张量竞技场、从本地快照加载分词器与处理器，以及 --api-server-count 大于 1 时按最少负载路由连接。 模型支持新增 EmbeddingGemma 2 全模态嵌入、MiniCPM-V 4.7 和 Nemotron 3.5 ASR，Transformers 建模后端支持视频输入；HiSparse 按请求驻留缓存可在 B200 上为 GLM-5.3-NVFP4 带来最高 58% 吞吐提升。安全修复覆盖三个 GHSA 编号，默认不再允许所有 CORS 来源，不受信任图像限制为光栅格式，共享内存多模态缓存句柄已签名，嵌套超过 64 层的 JSON schema 将被拒绝。破坏性变更包括放弃 Python 3.10 支持、收紧 CORS 默认、要求 transformers>=5.16.1,<5.20.0 与 tokenizers>=0.23.2、移除 torch.compile 序列并行与 AsyncTP 通道、级联注意力及 mamba_cache_mode="all"、max_tokens 不再从上下文窗口中预留、Responses API 推理流事件重命名。发布物包括 PyPI（CUDA 13.0）与 uv 安装方式、ROCm 轮子（rocm723）以及 XPU 轮子索引，另提供 Docker 镜像。

为什么重要：该版本的核心主题是结构化决策接口、低精度 KV 缓存在多硬件上的扩展，以及 Model Runner V2 的多项能力补全。低精度 KV 缓存优化围绕显存占用与吞吐的权衡展开；路由改进和 HiSparse 驻留缓存等优化针对高并发与长上下文场景。多项破坏性变更反映出发布方在逐步清理历史技术债，升级方需留意兼容性。
