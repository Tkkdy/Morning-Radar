vLLM v0.34.0 默认启用可扩展 KV cache，Model Runner V2 成为唯一 GPU runner

vLLM 发布 v0.34.0，包含来自 412 位贡献者的 1,061 个提交，新增 Mistral Large 4、MiniMax-M3.1-Flash、NVIDIA Nemotron-3.5-Transcribe、Liquid AI LFM3 系列等 10 个模型。可扩展 KV cache 在 CUDA 与 ROCm 上默认启用，改成按 CUDA graph 捕获与预热后的实际空闲显存定容；官方示例称 MiniMax-M3 在 H200 上的 KV cache 由 433k tokens 增至 672k tokens。同时 Model Runner V1 被移除，Model Runner V2 成为唯一 GPU runner，默认 block size 由 16 改为 64，gpu_memory_utilization 改为 1.0，ROCm 7.2 构建产物、QuTLASS/fp_quant、Marlin W4A8、Keye-VL 等被移除，并要求 huggingface_hub >= 2.0.0。

为什么重要：按预热后实际空闲显存定容的 KV cache 是本版本对吞吐影响最大的默认行为变化，倾向提升高并发缓存容量与首 token 延迟表现；但移除 V1 runner、改默认 block size 与收紧依赖，意味着升级需要主动核对启动参数、自定义 logits processor 与量化格式兼容性。

已上线
GitHub · vllm-project/vllm · Release 主来源 Release 发布于 2026-11-16

不确定性：官方给出的性能提升倍数缺乏独立基准复现；TPOT 上升 6%–18% 仅在部分 H200 模型与并发 128 条件下给出，其他硬件与负载下未知；摘要中推测解码的“Draft KV cache 与目标 dtype 匹配”条目被截断，需查阅 changelog。

已验证事实

  • vLLM 发布 v0.34.0，该版本包含 1,061 个提交，来自 412 位贡献者，其中 120 位为新贡献者。
  • v0.34.0 新增 10 个模型，包括 Mistral Large 4、MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe 等。
  • 可扩展 KV cache 在 CUDA 和 ROCm 上默认启用；KV cache 按 CUDA graph 捕获与预热后实际空闲内存来定容，而非估算（PR #56492）。
  • 官方示例称 MiniMax-M3 在 H200 上的 KV cache 由 433k tokens 增至 672k tokens。
  • 官方称在部分 H200 模型上，并发 128 时每 token 解码延迟可能上升，TPOT 增加 6%–18%；可通过 --gpu-memory-utilization 0.9 或 --no-enable-extensible-kv-cache 关闭。
  • Model Runner V1 已被移除（PR #63373），Model Runner V2 成为唯一 GPU runner；设置 VLLM_USE_V2_MODEL_RUNNER=0 会在启动时报错。
  • 默认 --block-size 由 16 改为 64（PR #63231），ROCm paged attention 仍使用 16。
  • 默认 gpu_memory_utilization 改为 1.0。
  • ROCm 7.2 相关构建产物被移除（PR #61939），改用 ROCm 10.0 wheels 与镜像。
  • 该版本要求 huggingface_hub >= 2.0.0，同时要求 tokenizers >= 0.23.3 与 timm >= 1.0.30（PR #64779）。
  • QuTLASS / fp_quant 被移除（PR #65230），Marlin W4A8 被移除（PR #65542）。
  • Keye-VL 与 Keye-VL-1.5 被移除（PR #64287）。
  • 新增模型清单包含 Mistral Large 4（1T 总参数 / 52B 激活，FP8 与 NVFP4，支持 NVIDIA Blackwell/Hopper 与 AMD MI350，PR #64534）、MiniMax-M3.1-Flash（PR #64111）、NVIDIA Nemotron-3.5-Transcribe（30B-A4B 语音模型，PR #64282）、Ricursive Ripple-65B Preview（PR #65745）、Zyphra ZAYA1（PR #65302）、Baidu Unlimited-OCR-2（PR #64016）、Liquid AI LFM3 系列（PR #65826、#65827、#65828）、NVIDIA Canary-1B-v2（PR #64215）、Ming3-ASR（PR #63585）、NVIDIA Parakeet TDT（PR #65005）。
  • 推测解码方面，suffix decoding 在 MRV2 上运行并使用 GPU speculator，不再需要 Arctic Inference（PR #60339）；新增声明式配置与 register_speculative_method 插件 API（PR #63205）；MRV2 draft-model speculator 支持 CUDA graphs（PR #60989）；自适应验证支持 XPress（PR #65175）。

分析

  • KV cache 改为按预热后实际空闲显存定容，是本版本对吞吐影响最大的默认行为变化；它倾向提升高并发下的缓存容量与 TTFT，但可能牺牲部分单 token 解码延迟。
  • 移除 Model Runner V1 与调整 block size 默认值，意味着升级需要主动检查启动参数与自定义 logits processor 的迁移路径。
  • 依赖与后端组合要求收紧（huggingface_hub >= 2.0.0、ROCm 10.0、移除 ROCm 7.2 与 fp_quant/Marlin W4A8），升级前需核对部署镜像与量化格式兼容性。

不确定性

  • 官方给出的性能提升倍数缺乏独立基准复现，实际收益取决于模型、硬件与并发配置。
  • KV cache 定容变化对 TPOT 的影响（6%–18%）仅在部分 H200 模型与并发 128 条件下给出，其他硬件与负载下的表现未知。
  • 摘要中推测解码的“Draft KV cache 与目标 dtype 匹配”条目被截断，完整细节需查阅 changelog。
