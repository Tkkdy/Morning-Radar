MCP Python SDK v2.2.0 发布：收紧重定向规则，新增会话超时与数量限制

Model Context Protocol 官方 Python SDK（modelcontextprotocol/python-sdk）v2.2.0 于 2026 年 9 月 7 日发布。核心变更包括：HTTP 客户端重定向只允许同 scheme/host/port，否则不从 http 升级到 https 的跨主机跳转会被拒绝；空闲 Streamable HTTP 会话默认 30 分钟过期（旧规范）；服务器同时最多持有 10000 个会话，超出返回 503；OAuth 客户端在 legacy 路径也会校验 issuer；新增 AuthSettings.validate_token_resource 选项；为 Streamable HTTP 服务器提供 session_idle_timeout 和 max_sessions 参数；修复 DELETE 释放会话、被拒请求残留会话、工具 outputSchema 内 $ref 解析等问题。发布说明还明确 tasks 扩展（SEP-2663）、DPoP（SEP-1932）和 jwt-bearer grant 尚未实现。

为什么重要：该 SDK 是 MCP 生态中最常被引用的 Python 实现。本次升级会直接影响现网依赖 HTTP 重定向的服务，尤其是把 HTTP 桥接到其他域名/端口以获取远程资源的代理类应用；同时，默认空闲 30 分钟过期与 10000 会话上限让服务端对新连接更敏感。如果现有部署里的客户端不配置相应参数，长连接或高并发场景可能开始出现失败。这也会提醒下游应用为升级 v2.2.0 预留兼容性测试。

已验证事实

  • modelcontextprotocol/python-sdk v2.2.0 于2026年9月7日发布，发布日期源自 GitHub Release 页面（https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.2.0）。
  • HTTP 客户端重定向仅在同一 scheme、host 和 port 内跟随，或将 http 升级为 https 到相同 host；其他重定向不被跟随，调用将失败。
  • 空闲的 Streamable HTTP 会话现在默认在无活动 30 分钟后过期（legacy <=2025-11-25 spec）。
  • 服务器同时最多持有 10000 个会话，拒绝新会话时返回 503。
  • OAuth 客户端在 legacy 路径上也检查授权服务器的 issuer，不匹配时抛出 OAuthFlowError。
  • 新增 MCPDeprecationWarning 警告，提示无 issuer= 参数的 ClientCredentialsOAuthProvider / PrivateKeyJWTOAuthProvider，以及设置了 resource_server_url 但未设置 validate_token_resource 的 AuthSettings。
  • 新增 AuthSettings.validate_token_resource 选项，只接受 TokenVerifier 报告的令牌。
  • 在 ClientCredentialsOAuthProvider 和 PrivateKeyJWTOAuthProvider 上新增 issuer= 参数。
  • 新增 session_idle_timeout 和 max_sessions 参数用于 Streamable HTTP 服务器入口。
  • 修复了客户端 DELETE 立即释放会话，以及被拒绝的打开请求不再留下会话。
  • 修复了工具 outputSchema 中的 $ref 仅在该 schema 内解析，无法解析时抛出 RuntimeError。
  • tasks 扩展（SEP-2663）、DPoP（SEP-1932）和 jwt-bearer grant 尚未实现。

分析

  • 行为变更和新增参数可能影响现有 2.x 用户，特别是 HTTP 重定向和空闲会话超时。
  • 此类发布通常用于向后兼容性改进和 bug 修复，预计对现有用法影响较小。
  • 已知的空白功能（tasks 扩展、DPoP、jwt-bearer）表明 SDK 仍有发展空间。

不确定性

  • 具体影响未量化，但行为变更可能影响依赖重定向或长会话的现有实现。
  • 新警告不会影响 2.x 的功能。
