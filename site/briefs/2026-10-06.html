vLLM 发布 v0.31.0

vLLM 发布 v0.31.0，共包含 717 个提交，来自 307 位贡献者（其中 96 位新贡献者）。

为什么重要：v0.31.0 是 vLLM 的一次大规模版本更新，提交数量和贡献者覆盖面显示社区活跃度较高。

已上线
GitHub · vllm-project/vllm · Release 主来源 Release 发布于 2026-10-05

不确定性：输入为 GitHub Release 说明，未提供独立性能基准或第三方复现结果。

查看详情

已验证事实

  • 该版本为 DeepSeek-V4.1-Flash 引入 FlashMLA mega attention，并搭配 V4.1 NVFP4 压缩 KV cache，已成为 SM100 默认配置（#56935）。
  • 新增 DeepGEMM sparse MQA logits 用于 indexer（#56254），以及 Mega-Gate 将 gate GEMM 与 expert selection 融合（#56266）。
  • 新 CLI `vllm preload` 启动 weight-cache daemon，在引擎重启期间将量化后权重保留在 GPU 内存中（#56680），支持数据并行（#57386）、MTP draft 模型（#57312）、`/health` 端点（#58552）和就绪等待（#58370）。
  • 实验性的 initialized-engine 快照（`vllm snapshot create/restore`）使用 CRIU 恢复完整初始化的 TP1 引擎（#51360）。
  • Model Runner V2 支持 draft-model speculative decoding（#43091）和自定义 logits processors（#56497）；新增 LiLiCorr drafter（#57934）。
  • 大规模服务方面新增 MoonEP balanced EP all2all 后端，通过 `--all2all-backend moonep` 启用（#52101）；支持 prefill context parallelism 与数据并行（#57075）。
  • 调度控制新增 `--max-num-active-seqs`，可独立于 `max_num_seqs` 限制 RUNNING 准入（#56758）。
  • 破坏性变更包括：按请求的多模态 kwargs 被门控（#58830）；移除 `tokenizer_mode="slow"`（#58545）；`--enable-mamba-fine-grained-prefix-cache` 重命名为 `--enable-mamba-shared-prefix-checkpoint`（#57382）；在线量化 `quantization="fp8"` 被 `fp8_per_tensor` 简写取代（#53585）；移除 Quark 静默在线量化（#51800）；移除 AllSpark INT8 W8A16 后端（#58001）。
  • `--enforce-eager` 现在也会禁用 JIT kernel warmup（#58197）；XPU graphs 被启用。

分析

  • 该版本重点优化 DeepSeek-V4.1-Flash 在 SM100 上的推理性能，涉及 attention、KV cache、MoE 融合及通信重叠等多个层面。
  • `vllm preload`、CRIU 快照和 Model Runner V2 的改进指向降低重启/恢复延迟与增强推测解码能力两个工程方向。
  • 大规模服务相关变更（MoonEP、context parallelism、NCCL M2N 等）表明项目在强化多节点与 RL 场景下的扩展性。
  • 多项破坏性变更集中在多模态安全、量化接口和废弃后端，升级时可能需要调整配置。

不确定性

  • XPU graphs 启用的具体范围与影响在摘要中未完整展开。
  • CRIU 快照功能标注为实验性，其生产环境稳定性尚不明确。
