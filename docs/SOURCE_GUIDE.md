# 信息源新增规范

## 选择标准

优先使用官方、稳定、公开、可追溯的 RSS/Atom 或 API。来源应与已配置主题直接相关，
具有明确发布者，并允许在不登录、不绕过访问控制的情况下读取必要元数据。

不添加要求验证码、登录、代理池或浏览器指纹伪装的来源；不复制付费或受版权保护文章
全文；不使用 Playwright 做生产采集。Hacker News 只作为社区讨论信号，不能替代一手事实。

## 优先级

- `high`：官方发布、项目 Release、监管/公司一手信息。
- `medium`：可靠技术媒体、作者清晰的工程博客。
- `low`：聚合和社区讨论，只用于发现或反应信号。

## 新增步骤

1. 在相应 YAML 中添加稳定 ID、名称、类型、真实 URL、优先级、主题和启用状态。
2. 为新来源准备最小 Fixture，只保留测试所需公开元数据和短摘录。
3. 增加成功、重复条目和来源失败测试，确保测试不访问网络。
4. 验证所有时间带时区，URL 未被 AI 或代码猜测，摘录长度受限。
5. 运行相关单元测试和 Fixture 集成测试后再提交。
